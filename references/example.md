# 对照实例

下面全部出自同一期播客（Next Token 第四期，Muse 那一段）的真实改稿过程。原始稿是照录音整理的发言人为轴的版本，成稿是发布版。

## 零、先看要点梳理长什么样

写文章之前先做的事实账本，按话题分组，一行一条，括号里是章节号：

```
## A. 它火了

1. 任何软件接进它的连接器商店，股价一天涨百分之十起步，有的涨百分之十三。Meta 涨到两万亿美金。（06）
2. 当年收购 Alexandr Wang 的公司时，很多人骂扎克脑子有问题，几百亿美元买这个；现在这个人一天让 Meta 涨了两万亿。（06）
3. 杨攀：Muse 就是新的 Store。原来是上苹果，现在你上的是 Agent。（06）
4. 日活只有五十万。（06）
5. 中文互联网圈对 Meta 的实际价值缺乏认知，因为 Meta 的主流产品我们日常不用。Threads 的日活其实很早就超过 Twitter，Facebook 的广告收入非常可怕，杨攀称之为美国腾讯。（06）
6. 杨攀在一轮大厂内部分享里说过：豆包本来是面向几亿人做的产品，因为 Codex 和 WorkBuddy 火了，掉头为一亿人做产品，回头还是得为几亿人做，结果被 Muse 在一个月之内打脸。（09）
7. 橘子：Muse 把 AI 泡沫推向了一个新的高峰。你有一亿日活，就是一亿台虚拟电脑。（09）
```

注意第 3、5、6、7 条里也写了名字。账本阶段名字全留，因为要让人看得出这条是谁给的、可不可信；到成文阶段再决定哪些署名留下。

## 一、拆脚手架：原始稿 763 字 → 成稿 265 字

**原始稿**

> 歸藏说，最能说明问题的是股价。任何软件只要加进 Muse 的连接器商店，那个软件的股价一天涨百分之十起步，多的时候一天涨百分之十三。Meta 自己涨到了两万亿美金，而 Muse 的日活只有五十万。
>
> 当年收购 Alexandr Wang 的公司时，很多人骂扎克脑子有问题，几百亿美元买了个这。歸藏说现在这个穿洞洞鞋、穿迷彩短袖的人，一天给 Meta 涨了两万亿美金。
>
> 杨攀的概括是，Muse 就是新的 Store。原来你是上苹果，现在你上的是 Agent。
>
> 中文互联网圈对 Meta 这家公司的实际价值非常缺乏认知，原因是 Meta 的主流产品我们日常几乎不用，但其实 Threads 的日活其实很早就超过 Twitter 了，Facebook 的广告收入也非常可怕，其实更好理解的类比是美国的腾讯。
>
> 杨攀上周刚在几个大厂内部做过一轮分享，他说豆包本来是面向几亿人做的产品，因为 Codex 和 WorkBuddy 火了，掉头为一亿人做产品，回过头来还是得为几亿人做，结果 Muse 一个月之内就把这个判断打脸了，不过中秋节后各家大厂都在加班研发类似产品。
>
> 橘子说 Muse 把 AI 泡沫又推向了一个新的高潮，他们讲的故事是，你有一亿日活，就需要一亿台虚拟电脑。

**成稿**

> 最能说明问题的是股价。任何软件只要加进 Muse 的连接器商店，股价一天涨百分之十起步，多的时候涨百分之十三。Meta 自己涨到了两万亿美金，而 Muse 的日活只有五十万。
>
> 当年 Meta 花几百亿美金买下 Alexandr Wang 的公司，外面骂声一片，说买了个什么。现在扎克伯格，穿洞洞鞋、迷彩短袖，一天给 Meta 涨两万亿美金。
>
> 一句话概括：Muse 就是新的 Store。原来你是上苹果，现在你上的是 Agent。
>
> 中文互联网圈对 Meta 的实际价值一向缺乏认知，因为它最主流的产品我们日常几乎不用。其实 Threads 的日活很早就超过 Twitter，广告收入也非常可怕。它是美国的腾讯。
>
> 杨攀刚从大厂内部做完一轮分享。他说豆包本来是面向几亿人做的产品，因为 Codex 和 WorkBuddy 火了，掉头为一亿人做，回过头来还是得为几亿人做，结果 Muse 一个月之内就把这个判断打脸了。中秋节后，各家大厂都在加班研发类似产品。
>
> Muse 把 AI 泡沫又推向了一个新的高潮。它们讲的故事是，你有一亿日活，就需要一亿台虚拟电脑。

改了什么：

- 六处「XX 说 / 的概括是」，删掉五处。只留杨攀那一处，因为下面那段是他的独家信息，需要署名认领。
- 长句拆开。「杨攀上周刚在几个大厂内部做过一轮分享，他说豆包……」拆成两句，转述结构变成一个独立的短句。
- 「很多人骂扎克脑子有问题，几百亿美元买了个这」，改成「外面骂声一片，说买了个什么」。原句是发言人对另一个人的评价，照抄等于文章作者在骂人；改成描述外界反应，语气还在，责任不落在作者身上。同时补出主语「Meta」，原文「当年收购 Alexandr Wang 的公司时」谁收购的没写。
- 三个「其实」删掉两个。口语里的重复连词落到纸面上非常刺眼。
- 「一句话概括：」这处提示性冒号其实是 AI 痕迹（人类每千字 0.08 处，AI 0.30 处），当时没改。这是全篇唯一一处。

## 二、人名：同一个人，一处留一处删

**原始稿**

> 歸藏说豆包的 Memory 之所以让人烦，是因为你跟它说一件事，它天天跟你磨叨，你都做完了它还在提。他把这里的问题归结成目标和信息被混淆了……歸藏说他以前试过用 Chat 管理自己的 To-Do List，把滴答清单都停了，过了一年发现什么都没管理好，于是又把滴答清单用了回来。

**成稿**

> 豆包的 Memory 之所以让人烦，是因为你跟它说一件事，它天天跟你磨叨，你都做完了它还在提。问题在于目标和信息被混淆了。……歸藏以前试过用 Chat 管理自己的 To-Do List，把滴答清单都停了。一年下来什么都没管理好，于是又用了回来。

同一个说话人，前半句删名，后半句留名。分别在于：前半句是一个判断，谁都能说，挂名只会让文章变啰嗦；后半句是他的亲身经历，只有他能认领。

同类保留：

- `杨攀今年上半年有一页 PPT 说过，2027 年的 AI 产品如果还让用户谈论 Key、MCP、Skill 这些概念，那肯定做不大。`（他本人的分享，可追溯）
- `橘子跟一位前 Google 日历的产品经理聊过这件事。那位产品经理说……`（一手信源，且对方不具名是合理的，因为这是转述而不是认领）
- `歸藏频繁用了两三天，免费的 Token 只用了百分之二三。`（使用体验）

反面写法：「有业内人士指出，Muse 就是新的 Store」。有人就写人。

## 三、标题：从名词短语改成读者的提问

| 原始稿 | 成稿 |
|---|---|
| 三、上一代做同一件事的叫 OpenClaw | 三、Muse 和 OpenClaw 的区别是什么？ |
| 四、真正难的是不让人烦 | 四、Muse 产品看似简单，实则细节拉满 |
| 五、一个看得见的结果 | 五、日历是不是普罗大众的刚需？ |

「一个看得见的结果」这种标题，读者看完不知道下一段要讲什么。换成问句之后，读者带着问题往下读，答案也不用一开始就给。

## 四、精简：砍掉的都在回答别的问题

整段删掉的有：

- Manus 的段子（「Manus 去掉 an 就是 Muse」）——本节讲的是股价和行业认知，段子不回答这个。
- 亚马逊封 Muse、Shopify 股价——顺手蹭的热度。
- 橘子写骑行软件的经历、Siri 新版弱智、iOS 上两个技术进展——第四节问的是「产品为什么体验差这么多」，这些讲的是别的事。
- 橘子举自家产品的心记功能——自我引用。

一条没砍的有：

- 具体数字与参数：`iPhone 18 Pro Max 跑个《赛博朋克 2077》都没问题`、`两英寸屏幕、前后摄像头、语音输入、视频输入输出、5G 和 eSIM`。
- 有画面感的原话：`你跟老婆是这么聊的吗？`、`我们为什么要把人生浪费在这些事上。`
- 一手体验：`免费的 Token 只用了百分之二三。`

砍的标准是「它在不在回答这一节的问题」，不是「这段写得好不好」。这也是为什么先定节、再砍：章法定了才知道哪一段是跑题的。

## 五、用原文：同一段内容的两种写法

出自另一期（英文单人访谈，Invest Like the Best 的 Noah Shinn）。第一版全篇直接引语 0 处，嘉宾的话被全部改写成概述，作者的评价是「改写太多了，有原文用原文啊」。

**第一版（概述）**

> 他说他不想造那个世界，大多数消费平台对用户免费、靠广告，品牌付钱让人买他可能并不需要的东西，他作为技术人不想造那个世界。
>
> 安全他分成两块：一块是敏感信息的存储，另一块是全新的问题。
>
> 变化出现在第三周。四成用户把一张个人信用卡交给了它。

**第二版（引语 + 段首接上文）**

> 大多数消费平台是另一个样子，对用户免费，广告推给用户，品牌付钱让人买他可能并不需要的东西。「这就是那个说法，如果你不付钱，你就是商品。作为一个程序员、一个技术人，我不想造那个世界。」
>
> 他们的原则是用户永远控制自己的数据，想给多少给多少，想收回随时收回。信任就是这么长出来的。三周之内，四成用户把一张个人信用卡交给了它。

改了什么：

- 判断和情绪的话全部还原成引语，前面挂「他说」。交代背景、串联上下文的部分继续用转述。改完直接引语汉字占比从 0 升到 35%。
- 段首不再每段摆一句自足判断（「安全他分成两块」「变化出现在第三周」），改成接上一段的线，或者直接进场景。改完段首自足判断句从 34% 降到 30%。
- 「信任就是这么长出来的」这类作者判断句留在段中、段尾，不放在段首。
- 开头删掉替读者摆的画面（「他坐在对面」「在节目开场时他抛出一个问题」），第一段直接交代这期是谁跟谁聊的。

**第三版：引号收一半，过渡语改最短**

第二版被作者退回来两次。一次是说引号太多：「我让你多用原文，不是让你都用引号，这种读起来很累。」另一次是说过渡句自己攒得太重：「你的小结过度其实可以非常简单，比如聊到支付，他说，聊到用户场景，他说，聊到商业化，他说，或者每个章节用一下人名也 ok。」

改法两条：

- 引号从 33 处收到 18 处，只在真正有画面、有分量的话上留引号（打电话那段、task accomplisher 那句、「我今晚要在纽约」），其余原话保持措辞降级成叙述（`他说他不想把简单的界面和有限的能力搞混`）。占比从 36% 降到 23%。
- 自己攒的过渡句全部换成短引导：`聊到支付，他说：……`、`聊到场景，他举了车的例子`、`聊到成本，他说……`；每节开头点一次人名。
